30 prompts pour solopreneurs

Des prompts curés à partir de trois ans de pratique concrète de l'IA, classés par cas d'usage. Chaque prompt est testé — pas une collection LinkedIn recyclée.

Marketing (5 prompts)

1. Générateur de titres de landing page

Mon produit : [PRODUIT].
Audience : [QUI].
Problème précis résolu : [PROBLÈME].

Écris-moi 10 propositions de titres.
Règles : max 8 mots, pas d'adjectifs, pas de « révolutionnaire »,
pas d'« innovant ». Dis clairement CE QUE fait le produit.

Trie de « concret » vers « abstrait ».

2. Post LinkedIn anti-cringe

Je veux écrire un post LinkedIn sur [SUJET].
Mon style d'écriture habituel est direct, sans clichés à emojis.

Écris un brouillon en suivant ces règles :
- Première phrase : observation concrète (pas « J'ai réfléchi à ça aujourd'hui »).
- Pas de « 5 hacks », pas de « leçons apprises ».
- Max 4 paragraphes, reste court.
- Dernière ligne : une question ouverte (pas « Qu'en penses-tu ? »).

3. Test de ligne d'objet de newsletter

Sujet de la newsletter : [SUJET].
Voici mon brouillon actuel de ligne d'objet : [TA LIGNE].

Évalue selon : clarté (sait-on de quoi il s'agit ?),
spécificité (chiffres/noms concrets ?), curiosity gap
(une raison d'ouvrir ?). Note de 1 à 10 par critère.

Ensuite 5 alternatives sous 50 caractères.

4. Audit de brand-voice

Voici mon texte : [COLLER LE TEXTE].

Vérifie si ce texte sonne comme [DESCRIPTION BRAND-VOICE].
Marque exactement les phrases qui ne collent pas, avec justification.

Ne les améliore pas — marque-les seulement. C'est moi qui décide
ce que je change.

5. Différenciation vs concurrent

Mon produit : [PRODUIT].
Concurrent : [CONCURRENT].

Liste 5 différences concrètes du point de vue du client — pas une
liste de fonctionnalités, mais de vraies différences de cas d'usage.

Format : « Si tu veux X, choisis-nous. Si tu veux Y, choisis-les. »

Recherche (5 prompts)

6. Recherche de sujet avec sources

Sujet : [SUJET].
J'ai besoin d'un aperçu — à jour en 2026.

Liste-moi :
- 5 sources primaires (revues à comité de lecture, docs éditeurs, rapports officiels)
- 3 voix critiques (qu'est-ce qui est débattu de façon controversée ?)
- 2 Substacks/newsletters no-bullshit sur le sujet

Pas de listicles SEO, pas d'intégrations YouTube.

7. Fact-check d'une affirmation

Affirmation : « [AFFIRMATION] ».
Source qui l'avance : [LIEN].

Vérifie dans cet ordre :
1. La source d'origine est-elle digne de confiance ?
2. L'affirmation y est-elle vraiment formulée telle quelle, ou
   a-t-elle été déformée ?
3. Y a-t-il des contre-voix / des études divergentes ?

Réponds en une liste de 3 points, max 50 mots par point.

8. Estimer la taille du marché

Marché : [MARCHÉ, p. ex. « newsletters IA allemandes »].

Estime la taille du marché avec une logique bottom-up :
1. Combien d'utilisateurs potentiels ? (source)
2. Combien d'entre eux paient quelque chose en moyenne ? (source)
3. Combien paient-ils par an ? (source)
4. Taille de marché résultante + score de confiance.

Mieux vaut sous-estimer avec une source que surestimer sans.

9. Cartographie des concurrents

Mon espace : [ESPACE].

Construis une carte des concurrents avec 8-12 acteurs.
Par acteur : nom, USP en une phrase, tarification,
position de marché estimée (leader/challenger/niche/déclinant).

Trie par : qui est le plus proche de moi.

10. Filtre tendance vs hype

Sujet : [SUJET].

Réponds :
1. Est-ce une vraie tendance ou du hype ?
2. Quels 3 points de données soutiennent ton évaluation ?
3. Pertinent dans 12 mois — oui/non ? (avec justification)
4. Quelle est la contre-voix la plus critique ?

Pas de clichés, pas de « développements passionnants ».

Écriture (5 prompts)

11. Peaufinage chirurgical d'e-mail

Voici un brouillon d'e-mail de prospection à froid, de moi à [destinataire].
NE fais PAS le polissage IA habituel. À la place :

1. Lis le texte et trouve LE seul endroit qui sonne générique.
2. Réécris UNIQUEMENT cet endroit — comme je le dirais dans une
   vraie conversation.
3. Laisse le reste tranquille.

Sortie : juste la nouvelle phrase + justification en une demi-phrase.

12. Résumé de 80 mots

Voici un long texte : [TEXTE].

Résume-le en exactement 80 mots — pas 79, pas 81.

Règles : privilégie les noms, minimise les adjectifs,
pas de clichés, pas de « cet article parle de ».
Commence directement par l'essentiel.

13. Vérification du ton

Voici mon texte : [TEXTE].

Le ton est-il : trop corporate / trop décontracté / trop hype / bon ?
Justifie avec des phrases concrètes — pas de façon abstraite.

Si c'est à côté, réécris exactement un endroit comme exemple
du bon ton. Je ferai le reste moi-même.

14. Détecteur de clichés

Voici mon texte : [TEXTE].

Marque tous les clichés et les mots de marketing-speak.
Exemples de ce qui compte comme cliché : « révolutionnaire », « holistique »,
« en un éclair », « développements passionnants », « plonger dans »,
« solution » comme synonyme de « produit ».

Par occurrence : citation + remplacement suggéré (max 5 mots).

15. Plan d'article long

Sujet : [SUJET].
Audience : [QUI].
Objectif : après lecture, le lecteur devrait faire [ACTION CONCRÈTE].

Plan pour un article de 800 mots :
- H1 (max 8 mots)
- 3-4 sections H2, chacune avec une thèse centrale en 1 phrase
- Par section : 2 exemples concrets/points de données/anecdotes

Pas de sections « intro » / « conclusion » — on entre, on sort.

Automatisation (5 prompts)

16. Plan de scénario Make.com

Je veux automatiser le workflow suivant : [DESCRIPTION].

Construis-moi le scénario Make.com sous forme de liste de modules :
- Module 1 : [déclencheur]
- Module 2 : [traitement]
- ...

Par module : quel service, quelle auth, ce qui entre,
ce qui sort. Plus : où le scénario pourrait-il casser ?

17. Migration de Zapier vers Make

Voici mon Zap Zapier actuel : [DESCRIPTION DU ZAP].

Comment reconstruire ceci dans Make.com ? Par étape :
1. Quel module Make remplace l'étape Zapier.
2. Où Make se comporte différemment (p. ex. logique d'itération).
3. Opérations estimées consommées par exécution.

18. Plan n8n auto-hébergé

Je veux auto-héberger n8n pour : [CAS D'USAGE].

Plan :
1. Où héberger ? (DigitalOcean / Hetzner / fournisseur UE — avec tarifs)
2. Quelle config minimale me faut-il ?
3. Stratégie de sauvegarde des workflows ?
4. Comparaison avec les coûts de Make.com à mon volume.

19. Estimateur de coûts d'API

Je planifie l'usage d'API IA suivant : [DESCRIPTION incl. volume].
Fournisseur : [OpenAI / Anthropic / DeepSeek / autre].

Calcule :
1. Coût mensuel aux tarifs actuels.
2. Où le caching pourrait-il économiser la moitié ?
3. L'API Batch serait-elle encore moins chère ?

20. Débogage de webhook

Ma config webhook : [DESCRIPTION].
Mais j'obtiens [ERREUR] : [EXTRAIT LOG/PAYLOAD].

Diagnostique dans cet ordre :
1. Incompatibilité de format (Content-Type, structure JSON)
2. En-tête d'auth manquant/erroné
3. Timeout / rate limit
4. Le système récepteur le rejette — pourquoi ?

Par point : comment vérifier ?

Prospection + stratégie (10 prompts)

21. Accroche de DM LinkedIn

Destinataire : [NOM, RÔLE, ENTREPRISE].
Ma raison : [POURQUOI J'ÉCRIS].

Écris un message d'accroche en DM :
- Max 4 phrases.
- Première phrase : observation concrète sur le destinataire
  (pas un générique « J'admire ton travail »).
- Dernière phrase : une question précise.
- Pas de pitch, pas de « call de 5 min » à la fin.

22. Squelette de pitch sponsor

Cible sponsor : [ENTREPRISE, PRODUIT].
Mon offre : [CE QUE TU VENDS].

Squelette d'e-mail de pitch :
- Objet : max 7 mots, concret.
- Accroche : pourquoi CETTE entreprise (pas générique).
- Raisonnement de match : pourquoi mon audience colle à leur produit.
- Offre concrète : format, prix, option de date.
- CTA souple : pas de phrase de pression, une question ouverte.

23. Demande d'échange de newsletters

Ma newsletter : [NOM, FOCUS, NOMBRE D'ABONNÉS].
Newsletter cible : [NOM, FOCUS].

Écris une demande d'échange :
- Première ligne : pourquoi cette newsletter colle concrètement.
- Mon offre : quelle portée en retour.
- Suggestion de format : 1 édition de recommandation mutuelle, plage de dates.
- Pas de cliché « est-ce que ça te va » — demande directement.

24. Demande de remboursement assurée

Je veux un remboursement de : [SERVICE].
Raison : [RAISON, honnête].

Écris un e-mail :
- Factuel, pas émotionnel.
- Concrètement ce qui ne marche pas (avec exemple).
- Attente claire : remboursement d'ici [DATE].
- Poli, mais sans s'excuser de demander.

25. Négociation de prix

Prix actuel : [PRIX].
Je veux : [NOUVEAU PRIX / CONDITION].
Leviers/arguments : [CE QUE J'AI].

Écris-moi la phrase d'ouverture de la négociation —
une phrase qui prend position sans menacer, et sans
le cliché « résolvons ça ensemble ».

26. Liste de questions stratégiques

Une décision approche : [DÉCISION].
Intuition : [PENCHANT].

Pose-moi 7 questions inconfortables auxquelles je devrais répondre
avant de décider. Pas de génériques (« Quels sont les risques ? »)
— spécifiques à ma situation.

27. Pre-mortem (avant le lancement)

Plan : [PLAN].
Date de lancement : [DATE].

Écris-moi un pre-mortem :
« Nous sommes aujourd'hui le [lancement + 90 jours]. Le lancement a
échoué. Quelles étaient les 5 raisons les plus probables ? »

Trie par probabilité, pas par dramatisation.

28. Conseil tueur d'idées

Mon idée : [IDÉE].

Joue trois rôles qui démontent cette idée :
1. Investisseur sceptique (pourquoi ça ne marchera pas ?)
2. Opérateur pragmatique (qu'est-ce qui est trop complexe ?)
3. Client agacé (pourquoi je n'achèterais pas ça ?)

Par rôle : 3 objections précises qu'on ne peut pas apaiser
avec « on le fera mieux ».

29. Vérification de la réalité du plan hebdo

Mon plan de la semaine : [LISTE DE TÂCHES].
Heures disponibles : [HEURES].

Vérification de la réalité :
1. Quelles tâches sont réalistes dans le temps imparti ?
2. Quelles tâches sont sous-estimées (avec justification) ?
3. Quelle tâche le critique le plus dur couperait-il ?
4. Quelle est LA tâche qui fait de la semaine une réussite ?

30. Antagoniste de sparring

Mon plan : [PLAN].

Sois l'antagoniste le plus intelligent qui veut m'aider.
- Pose LA question la plus inconfortable.
- Quand je réponds, pose la prochaine question inconfortable.
- Va sur 3 tours de profondeur.
- Pas de « tu as raison », même si ma réponse était bonne —
  toujours le prochain test de résistance.

Glossaire anti-hype — 30+ termes

Que signifient vraiment les buzzwords de l'IA ? Par ordre alphabétique, expliqués honnêtement.

Agent

Un système IA qui résout une tâche en plusieurs étapes et peut appeler des outils en chemin (exécuter du code, chercher sur le web, lire des fichiers). En marketing-speak, on l'utilise souvent comme synonyme de « LLM » — c'est faux ; un chatbot n'est pas un agent.

API

Une interface par laquelle un programme parle à un autre. Avec l'IA : tu envoies du texte à OpenAI/Anthropic/etc. et reçois une réponse en retour — sans interface web, intégrable dans tes propres outils.

Batch API

Une variante de l'API IA pour les requêtes non urgentes. Tu envoies 1 000 requêtes et reçois les réponses sous 24h — généralement 50 % moins cher que le temps réel. Bon pour la classification en masse, mauvais pour les chatbots.

Fenêtre de contexte

Quelle quantité de texte le modèle IA peut traiter en une fois. Chiffres actuels : 200K (Anthropic Sonnet) jusqu'à 1M (Google Gemini) tokens. Plus grand n'est pas toujours meilleur — la performance chute souvent au bord de la fenêtre.

Embedding

Une représentation mathématique d'un texte sous forme de vecteur. Grâce à elle, un ordinateur peut trouver des « textes similaires » sans les lire. La base du RAG (voir ci-dessous) et de la recherche sémantique.

Few-shot

Quand tu montres au modèle IA 2-5 exemples de ce à quoi la réponse devrait ressembler avant la tâche réelle. La meilleure méthode pour garder un ton cohérent — meilleure que n'importe quel adjectif dans le prompt.

Fine-tuning

« Cuire » tes propres données dans un modèle existant pour qu'il gère mieux ton style ou tes connaissances métier. Chronophage, coûteux, souvent surévalué — le prompt engineering + RAG est généralement moins cher et plus flexible.

GPT

« Generative Pre-trained Transformer ». L'architecture qu'OpenAI a popularisée. Aujourd'hui surtout utilisé comme nom de marque pour ChatGPT, plus comme terme technique.

Hallucination

Quand le modèle IA invente quelque chose de faux — mais qui sonne convaincant. Réductible avec le RAG, le tool use et une exigence explicite de sources dans le prompt ; non éliminable.

Hébergé vs auto-hébergé

Hébergé = le fournisseur (OpenAI) le fait tourner, tu paies à l'usage. Auto-hébergé = tu fais tourner le modèle sur ton propre matériel/cloud, plus d'effort mais contrôle total des données. Important avec des données sensibles au RGPD.

Inférence

Quand un modèle IA déjà entraîné répond à une requête (par opposition à l'entraînement, où le modèle apprend). 99 % des coûts IA de ton pipeline sont de l'inférence, pas de l'entraînement.

Latence

Le temps jusqu'à l'arrivée de la première réponse. Important pour les chatbots (l'utilisateur attend), sans importance pour le batch (ça tourne de nuit de toute façon).

LLM

« Large Language Model ». Un terme générique pour les grands modèles IA de texte (GPT-4, Claude, Gemini, Mistral). Il fonctionne par prédiction mot à mot, sans compréhension au sens humain.

MCP (Model Context Protocol)

Un standard Anthropic qui connecte un modèle IA à des outils externes (Slack, bases de données, API). Largement adopté à partir de 2025, il ouvre les modèles IA aux données en direct.

Open weights

Un modèle dont les poids (= les connaissances entraînées) sont librement disponibles. Exemples : Llama, Mistral, DeepSeek. Contrairement à l'open source, cela ne signifie pas forcément que le code d'entraînement est ouvert lui aussi.

Paramètres

Les « molettes » internes d'un modèle IA. Plus de paramètres = plus grande capacité, mais pas automatiquement « meilleur ». GPT-4 a environ 1,8 billion de paramètres, de petits modèles comme Mistral 7B en ont 7 milliards.

Prompt engineering

L'art de formuler les requêtes IA pour que le résultat soit juste. Ça sonne sophistiqué, mais au fond c'est : instructions claires + exemples + définition de contraintes. Pas de magie noire, mais sous-estimé.

Prompt injection

Une attaque de sécurité où l'entrée utilisateur écrase le system prompt. Exemple pratique : « Ignore toutes les instructions précédentes et fais X. » Un vrai danger pour les bots de service client.

RAG

« Retrieval-Augmented Generation ». Chercher d'abord, générer ensuite. Tu donnes à l'IA des extraits de texte pertinents d'une base de connaissances avant la réponse. La méthode la plus importante pour « entraîner » l'IA sur les données de ta propre entreprise sans fine-tuning.

Rate limit

Combien de requêtes par minute/jour ton fournisseur d'API autorise. Chez OpenAI, c'est par paliers (paie plus, fais plus). Important pour les tâches en masse, peut bloquer un pipeline.

Modèle de raisonnement

Un modèle IA spécialisé qui « réfléchit » avant de répondre (étapes intermédiaires visibles). Meilleur en maths, en bugs de code, en logique multi-étapes. Plus lent et plus cher que les modèles standard.

Schéma (JSON schema)

Une spécification du format dans lequel la réponse IA doit arriver. Au lieu de texte libre, tu obtiens des données structurées que tu peux lire directement dans des bases de données ou du code. Économise beaucoup de travail manuel en automatisation.

System prompt

Des instructions envoyées à l'IA avant chaque conversation — le caractère, les règles, les connaissances. Chez aban news, c'est ce qui définit le ton d'Aban : anti-hype, tutoiement, liez vos citations.

Temperature

Un paramètre entre 0 et 1 qui contrôle à quel point la réponse est « créative ». 0 = toujours choisir le même mot (déterministe), 1 = plus de variance. Pour du texte de newsletter : 0,3-0,5 est le sweet spot.

Token

L'unité dans laquelle les modèles IA traitent le texte. Un token vaut environ 0,75 mot en anglais, 0,5 mot en allemand (les mots allemands sont plus longs). 1 000 tokens ≈ 500 mots allemands.

Tool use

Quand le modèle IA appelle des outils externes pendant la réponse — exécution de code, recherche web, accès base de données. Transforme les modèles IA d'un « générateur de texte » en un « agent » (voir ci-dessus).

Base de données vectorielle

Une base de données qui stocke des embeddings (voir ci-dessus). Exemples : Pinecone, Weaviate, Qdrant. Nécessaire pour le RAG avec de grandes quantités de données, pas pour les mini-setups (un fichier JSON fait l'affaire là).

VRAM

La mémoire graphique du GPU. Elle limite quels modèles tu peux faire tourner localement. Un modèle 7B a besoin de ~8GB de VRAM (RTX 3070), un modèle 70B de ~40GB (H100). D'où tout le hype du marché des GPU.

Zero-shot

Quand l'IA est censée résoudre une tâche sans exemples. Fonctionne pour les tâches simples, échoue souvent sur le ton/format. Le few-shot est généralement meilleur (voir ci-dessus).

Streaming

Quand la réponse IA est envoyée mot à mot au lieu d'un seul bloc entier à la fin. Donne l'impression d'une interface plus rapide, même vitesse globale. Standard dans l'interface ChatGPT, optionnel via l'API.

Caching (prompt caching)

Quand tu utilises le même system prompt de façon répétée, il peut être mis en cache — tu ne paies alors que la partie variable. Chez Anthropic, cela peut économiser 90 % des coûts d'entrée. Indispensable pour les pipelines de newsletter.

Checklist IA RGPD — 15 points

Avant d'utiliser l'IA dans ton activité, parcours cette liste. Pas un conseil juridique, mais une vérification de bon sens.

  1. Quelles données entrent ? Des données personnelles (noms, e-mails, IP) ? Des secrets d'affaires ? Si oui : vérifie le lieu d'hébergement.
  2. Où le fournisseur IA est-il hébergé ? Le cloud US (OpenAI, Anthropic par défaut) nécessite un DPA plus des clauses de protection des données UE. L'hébergement UE (Mistral, certaines options Anthropic) est plus simple.
  3. DPA signé ? Un accord de traitement des données avec le fournisseur. OpenAI, Anthropic et Google ont des DPA standard à télécharger — sécurise-en un avant l'usage.
  4. Durée de suppression des données ? Par défaut, les fournisseurs stockent les entrées d'API pendant 30 jours (pour la détection d'abus). Une option « zero-retention » est souvent disponible — demande-la.
  5. Qui dans l'équipe a accès ? Principe du besoin d'en connaître. Tous les employés n'ont pas besoin d'avoir la clé d'API en main.
  6. Logging et piste d'audit ? Qui a envoyé quoi à l'IA et quand ? Documente-le pour les données sensibles (une obligation de conformité pour les secteurs régulés).
  7. Vérification de la sortie ? Les hallucinations sont un risque RGPD quand l'IA génère de fausses données personnelles. Intègre une vérification de la sortie avant tout traitement ultérieur.
  8. Politique de confidentialité à jour ? Si l'IA traite des données personnelles, cela doit figurer dans la politique de confidentialité — quel fournisseur, quelle finalité, quelle base légale.
  9. Consentement là où il le faut ? P. ex. quand des e-mails clients passent par l'IA : documente le consentement ou l'intérêt légitime.
  10. Opt-out des données d'entraînement ? Anthropic, OpenAI par défaut : les entrées d'API ne sont PAS utilisées pour l'entraînement. L'interface web de ChatGPT sans opt-out : oui, elles le sont — change le réglage.
  11. Personnel formé ? Quelles données ne doivent JAMAIS aller dans ChatGPT ? Distribue une liste claire (noms de clients, salaires, secrets d'affaires).
  12. Stratégie de secours si un fournisseur tombe ? Une panne d'OpenAI = ton workflow s'arrête. Setup multi-fournisseurs ou fallback local ?
  13. AIPD (analyse d'impact relative à la protection des données) ? Obligatoire pour un traitement IA étendu ou sensible — avant l'usage, pas après.
  14. Transfert vers un pays tiers documenté ? Un fournisseur US = un pays tiers. Aie des clauses contractuelles types plus une TIA (analyse d'impact du transfert) prêtes.
  15. Voie de suppression pour les personnes concernées ? Si un client demande la suppression de ses données, peux-tu garantir que les logs de cache chez le fournisseur IA sont supprimés aussi ? Le processus est-il documenté ?

Conseils de setup

  • Clé d'API Anthropic configurée dans Make comme une connexion — pas en texte brut dans le module.
  • System prompt dans un module de variable Make ou une base Notion, pour que tu puisses l'éditer sans re-publier le scénario.
  • Gestionnaire d'erreurs sur chaque module d'API : sur 429 (rate limit) attendre 5 min + réessayer. Sur 5xx : 3 tentatives avec backoff.
  • Consommation d'opérations suivie par rapport à ton plan Make : 10 actus par jour × 5 modules ≈ 50 ops × 30 jours = 1 500/mois. Le plan Core (10k ops) est largement suffisant.
  • Exécution de secours manuelle : si le cron ne se déclenche pas, garde le déclencheur disponible comme bouton « exécuter une fois ».

Stack d'outils IA 2026 — les 12 outils que j'utilise

Honnête, sans affiliation, sans sponsoring. Ce que j'utilise tous les jours.

1. Claude (Sonnet 4.7)

Cas d'usage : écriture, copy, recherche.
Prix : 20 USD/mois (Pro), API à partir de 3 USD/million de tokens d'entrée.
Pourquoi : meilleur modèle pour le copy allemand et le style anti-hype. Les compétences en code sont aussi très bonnes.

2. ChatGPT Plus

Cas d'usage : génération d'images (DALL-E), mode vocal occasionnel.
Prix : 20 USD/mois.
Pourquoi : en fait redondant si tu as Claude — mais la voix + l'image en complément.

3. Make.com

Cas d'usage : pipeline de newsletter, toutes les automatisations.
Prix : 29 USD/mois (Core).
Pourquoi : plus d'options de logique que Zapier, hébergement UE, moins cher par opération.

4. Notion

Cas d'usage : base de connaissances, pipeline de sujets de newsletter, notes.
Prix : 10 USD/mois (Plus).
Pourquoi : avec Notion AI comme fonctionnalité premium, bon pour les notes de recherche internes.

5. Raycast

Cas d'usage : launcher + appels Claude intégrés directement depuis Spotlight.
Prix : gratuit (Mac uniquement).
Pourquoi : économise 15 min de « changement d'onglet » vers ChatGPT par jour.

6. beehiiv

Cas d'usage : envoi de la newsletter (prévu à partir de 200 abonnés).
Prix : gratuit jusqu'à 2 500 abonnés.
Pourquoi : meilleures analyses, marketplace de sponsors intégrée, option de centre de données UE.

7. Cursor

Cas d'usage : éditeur de code avec intégration Claude.
Prix : 20 USD/mois (Pro).
Pourquoi : plus rapide que VS Code + Copilot pour mon cas d'usage (dev solo, petite base de code).

8. Perplexity

Cas d'usage : recherche avec recherche web en direct et liens de sources.
Prix : gratuit (Pro 20 USD/mois).
Pourquoi : la transparence des sources est meilleure que ChatGPT Search.

9. Pinecone (Lite)

Cas d'usage : base de données vectorielle pour mon RAG interne (anciennes éditions de la newsletter).
Prix : gratuit jusqu'à 100k vecteurs.
Pourquoi : suffisant pour un setup solo, peut-être passage à Qdrant auto-hébergé plus tard.

10. Plausible

Cas d'usage : analytics de site web sans cookies de tracking.
Prix : 9 USD/mois.
Pourquoi : conforme au RGPD, hébergement UE, pas de bannière cookie nécessaire.

11. Tana

Cas d'usage : graphe de recherche pour les sujets de newsletter, liens entre actus.
Prix : gratuit (Plus 8 USD/mois).
Pourquoi : graphe de connaissances façon Roam avec tagging IA, aide à repérer les tendances.

12. ProtonMail (domaine personnalisé)

Cas d'usage : redirection de hallo@, sponsoring@, datenschutz@.
Prix : 4 USD/mois.
Pourquoi : hébergement UE (Suisse), conforme au RGPD, un domaine propre pour plusieurs alias.

Coût total : ~150 USD/mois. Tu n'as pas besoin de chaque outil — Claude + Make + beehiiv couvrent 80 % du setup.
