## Lehren
- **`concat` auf `collection.products` liefert in Shopify eine leere Liste** (ohne Fehlermeldung, gemessen mit einer Testvorlage); der Umlauf am Poolende braucht zwei Schleifen (`offset` bis zum Ende, dann `limit` vom Anfang). In LiquidJS wäre `concat` durchgegangen: ein Test in einer fremden Engine beweist die Shopify-Engine nicht.
- **Testvorlage statt Livetest:** eine Datei `templates/page.lxtest.liquid` im MAIN-Theme (mit `{% layout none %}`) und die Adresse `/pages/<bestehende Seite>?view=lxtest` rendern beliebiges Liquid mit den echten Sammlungen, ohne die Startseite zu berühren; danach Vorlage und Test-Snippets wieder löschen (Seite ohne Weiterleitung wählen: `/pages/kontakt` leitet um).
- `divided_by` rechnet in LiquidJS mit Kommazahlen, in Shopify ganzzahlig: im Test die Shopify-Rechnung nachbauen.
- Ein fester Schrittwert in einer Rotation mit wechselnder Fenstergrösse kann an einer Reihe stillstehen (ggT mit der Zahl der Startwerte): Schritt aus Primzahlen wählen, die M nicht teilen, und im Test für alle Grössen die Zahl der erreichten Startwerte zählen.
- Automatisch gewählte Pools (Bewertung, Tags, Marge) lieferten viele schwache Bilder: Infografiken, ein Titel «Business-Rucksack» über dem Foto einer Umhängetasche, «Camouflage-Jacke» über einer dunkelblauen Jacke, eine Powerbank mit dem Bild einer Klimaanlage. Pools nur aus gesichteten Produkten bauen; die Automatik schlägt nur vor.
- `Liquid` kennt nur 20 `all_products`-Zugriffe je Seite: Produkte als Objekte aus Sammlungen lesen.
